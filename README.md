# Мабетэк

Сайт компании: железнодорожные услуги и аренда помещений в Хабаровске.

## Состав

- `frontend/`: Next.js App Router, React, TypeScript, CSS Modules. Пять основных страниц, каталог и карточки помещений, форма, мобильное меню.
- `backend/app/`: FastAPI, SQLAlchemy, PostgreSQL, SQLAdmin. Публичное API отделено от администрирования; воркер отправляет уведомления из БД.
- `backend/migrations/`: версионированная схема Alembic.
- `docs/acceptance.md`: поведение, зафиксированное тестами до реализации.
- `deploy/`, `compose.yaml`: Caddy, контейнеры и постоянные данные.

Утверждённый макет Sites остаётся отдельным проектом. Папка `sites/` намеренно исключена из этого репозитория.

## Быстрый запуск через Docker

1. Установить Docker с Compose. Скопировать `.env.example` в `.env`.
2. Сгенерировать разные случайные `POSTGRES_PASSWORD` (hex, без специальных символов URL) и `SECRET_KEY`, например `openssl rand -hex 32`.
3. Получить хеш пароля администратора:
   ```sh
   cd backend
   uv sync --frozen
   cd ..
   backend/.venv/bin/python scripts/admin-password.py
   ```
   Скопировать вывод в `.env`. Кавычки вокруг хеша сохранять: внутри есть символы `$`.
4. Создать `media/` и запустить:
   ```sh
   mkdir -p media
   docker compose up --build -d
   docker compose ps
   ```
5. Открыть `http://localhost`, админку — `http://localhost/admin/`. Логин из `.env`. Миграция выполняется перед стартом API.

Если порты 80/443 заняты, использовать свободные порты в локальной копии Compose и согласованно поменять `PUBLIC_ORIGIN`, `SITE_URL`, `SITE_ADDRESS`. Для разработки обычно удобнее запускать Node/Python напрямую.

## Локальная разработка

Нужны Node 22, Python 3.12+, uv и отдельная PostgreSQL-база.

```sh
cd backend
uv sync --frozen
# Установить DATABASE_URL, SECRET_KEY, ADMIN_PASSWORD_HASH,
# PUBLIC_ORIGIN=http://localhost:3000, SECURE_COOKIES=false.
uv run alembic upgrade head
uv run uvicorn app.main:create_app --factory --reload --port 8000
```

В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Next проксирует `/api/*` на `127.0.0.1:8000`. Для админки при прямом открытии порта 8000 временно задайте `PUBLIC_ORIGIN=http://localhost:8000`, либо используйте Caddy, чтобы весь сайт был на одном origin. В производстве API доступен только внутри сети Compose; доверять forwarding-заголовкам можно только при таком размещении. У локального uvicorn по умолчанию ограниченное доверие к прокси.

## Заполнение реальными данными

- Контакты, название юрлица, адрес и утверждённый текст политики: `frontend/src/content/company.ts`.
- Тексты страниц: `frontend/src/app/`. В первом релизе это редакционные исходники, не CMS.
- Помещения: `/admin/` → «Помещения». Тип `office` или `warehouse`, `slug` латиницей, черновик по умолчанию. Поля площади и цены необязательны. Флаги «Свободно» и «Опубликовано» независимы.
- Фото помещений: положить подготовленный JPG/PNG/WebP в `media/`, указать `/media/filename.jpg` в карточке. Загрузка файлов через админку в эту версию не входит. Каталог отдаёт только опубликованные карточки; пути проверяются при сохранении.
- Изображения главной сейчас иллюстративные из выбранного макета, **не фотографии объектов компании**. Источники и ограничения описаны в `docs/assets.md`. Перед коммерческой публикацией заменить фото и подготовить чистый файл логотипа.
- После утверждения политики указать `PRIVACY_VERSION`, например дату редакции, и `LEADS_ENABLED=true`. До этого форма закрыта. Нужны также SMTP и `NOTIFICATION_TO`.
- Заявки: `/admin/` → «Заявки». Можно менять статус и служебную заметку. Исходный контакт, текст и версия согласия доступны в подробностях и не редактируются.
- «Уведомления» показывает попытки и ошибки доставки. Сбой SMTP не удаляет заявку; воркер повторяет отправку с задержкой до часа. Доставка как минимум один раз: при аварии после принятия SMTP возможен дубль.

## Тесты

```sh
cd backend
uv run pytest --cov=app --cov-report=term-missing
# Для интеграционной проверки PostgreSQL:
TEST_DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST/DEDICATED_TEST_DB uv run pytest
```

**Тестовая БД должна быть отдельной:** фикстура удаляет и создаёт таблицы. Не указывать рабочую БД. Без переменной тесты используют временные SQLite-файлы.

```sh
cd frontend
npm run build
npm run typecheck
npx playwright install chromium
npm run test:e2e
```

Playwright проверяет desktop/mobile, навигацию, форму (ошибка/повтор/успех), закрытый приём заявок и 404. Сценарии формы используют подмену ответов API; реальное сохранение/уведомления проверяет pytest. GitHub Actions запускает обе группы, миграции и проверки PostgreSQL. Это покрытие согласованных сценариев, не обещание отсутствия всех ошибок.

## Производство и обслуживание

См. `docs/operations.md`. Отсутствующие домен, почтовый аккаунт, сервер и реквизиты нельзя заменить кодом. До их настройки версия работает как локальный сайт/стенд, а не как открытый канал заявок.
