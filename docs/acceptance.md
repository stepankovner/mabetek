# Контракт первой версии

Тесты написаны до прикладного кода. Они фиксируют наблюдаемое поведение, но не доказывают отсутствие всех ошибок. Новые требования дополняются отдельными тестами.

## Публичная часть
- Главная, железнодорожные услуги, аренда, о компании, контакты доступны без авторизации; каждая страница имеет заголовок и метаданные.
- Оба направления видны на главной. Нет выдуманных телефонов, площадей, цен и гарантированных сроков.
- Каталог показывает только опубликованные помещения. Можно выбрать тип помещения; недоступные и черновые карточки не выдаются как свободные.
- Неизвестная карточка возвращает 404. Ошибка сервиса отличается от пустого каталога.
- Заявка: имя, контакт, направление, сообщение, согласие. Сервер самостоятельно проверяет все поля. HTML не исполняется.
- Повтор с тем же Idempotency-Key не создаёт вторую заявку. Тот же ключ с другим содержимым даёт 409.
- Неверные данные не сохраняются. Публичного списка заявок нет.
- Ограничение частоты хранится в БД и не зависит от одного процесса. Поддельный X-Forwarded-For напрямую приложению не доверяется.
- При неподтверждённой политике персональных данных приём заявок выключен: сайт предлагает настроенные прямые контакты.

## Данные и администрирование
- Заявка и задача уведомления сохраняются одной транзакцией; сбой почты не теряет заявку.
- Почтовый воркер повторяет ошибки с задержкой; успешные уведомления повторно не отправляются. SMTP допускает дубликат при сбое после отправки до фиксации транзакции.
- Админка требует входа. Пароль хранится как Argon2-хеш в настройках окружения, сессия подписана, имеет срок жизни.
- Чужой Origin не может изменять данные админки. Вход ограничен по частоте.
- Администратор управляет помещениями и статусами заявок. Служебные идентификаторы, согласие и исходное содержимое заявки не редактируются.
- Миграции создают схему с нуля в PostgreSQL; повторное применение безопасно.

## Эксплуатация
- Docker Compose: PostgreSQL, миграции, API, почтовый воркер, Next.js, Caddy.
- База не публикуется наружу. Секретов в git нет. Медиа и база сохраняются в volumes.
- Readiness проверяет БД. Нет ошибки отправки, замаскированной под успех.
- Резервирование и восстановление описаны; окончательная публикация требует контактов, прав на изображения, политики и конфигурации домена/SMTP.
